## Topical map — patterns from `~/work/library`

The section-8 topical map composes patterns from the standards knowledge base rather
than inventing interaction:

| Pattern | Source object | Applied as |
|---|---|---|
| **Button (toggle)** | `aria-apg/patterns/Button.md` | Subtopic chips are toggle buttons exposing `aria-pressed`. They began as Disclosure triggers with `aria-expanded`; once selection became multi-select, disclosure no longer described the control and the state moved to `aria-pressed`, which the pattern is explicit about. |
| **Drawer — Accessibility** | `ant-design/component-details/Drawer-Accessibility.md` | Escape dismisses, focus returns to the triggering chip, the pane is labelled by its heading, a labelled close control is always present. |
| **Progressive disclosure** | `primer/patterns/Progressive-disclosure.md` | The map carries structure only; the evidence is deferred to the pane *and* to a fetched sidecar, so the page costs 145 KB rather than 770 KB. |
| **Overflow content** | `carbon/patterns/Overflow-content.md` | Every matching page is listed. Rows render 40 at a time behind "Show N more of M remaining" — progressive reveal, never a silent cap. An earlier build capped at 25, which the pattern's "without hiding information users need" rules out. |
| **Empty states** | `carbon/patterns/Empty-states.md` | An empty intersection states that no page carries all selected subtopics and suggests removing one. |

### Deliberate deviation

Ant's Drawer "behaves as a dialog" — modal and focus-trapped. **This pane is not modal.**
It is `role="complementary"` beside a map the reader is still scanning, so trapping focus
would block moving between subtopics, which is the primary interaction. It borrows
Drawer's dismissal and focus-restoration contract without its modality.

### Integration with the review widget

- Chips are `<button>`, so the widget's interactive-control exemption lets them toggle instead of opening a comment composer.
- The pane sits outside `<main>`, so widget anchoring ignores its fetched rows while the map itself stays commentable.
- In review mode the pane offsets below the banner and clear of the comments sidebar at ≥1280px.
- One logical topic may render several chips (shared subtopics appear in each category plus the register); pressed state is synced across all of them.

## Contract points honoured

- **Inert by default** — no `?review=1` yields no widget CSS, no widget module, no storage read. Only the floating `.review-toggle-btn` (per `inert-entry-button.md`), which carries its own inline style. **Verified in browser.**
- **CSS isolation** (`css-isolation.md`) — every rule scoped under `[data-review-mode="on"]`; `.review-` prefix on chrome roots only; state via `.has-comment` / `.has-applied-comment` classes.
- **JS isolation** (`js-isolation.md`) — single top-level IIFE; only global is `window.__reviewFivestar`.
- **TDZ-safe init** — cfg guard and `init()` are the final statements in the module.
- **Status indicators** (`comment-status-indicators.md`) — full outline (red open / green resolved) plus a vertical dot stack outside the right border.
- **Comment lifecycle** (`comment-lifecycle.md`) — `pending / applied / archived`, with Apply / Edit / Archive / Restore / Delete per row.
- **`anchorEmpty: ['td']`** (`commentable-everything.md`) — the hub is mostly data grids; a reviewer needs to flag an empty cell.
- **Chrome not anchored** — the nav sidebar is `<nav>`, deliberately excluded.

## Deviations from canonical

1. **Storage is `localStorage`, not Firebase RTDB.** `credo-712c4` belongs to a different client, and standing up a Firebase project for this engagement is a decision, not a default. Consequence: **comments are per-browser and not shared between reviewers.** Set `ADAPTER: 'rtdb'` and populate `FIREBASE_CONFIG` in `hub.config.js` to move to shared persistence.
2. **Version query on widget asset URLs** (`?v=1.0.2` in `review-bootstrap.js`). The dynamically-injected CSS/JS otherwise persist in the browser's memory cache across reloads — including hard reloads — so an edited widget silently keeps running old code. Surfaced during verification. Bump on every widget edit. *Candidate to harvest upstream: this will bite any consumer iterating on a composed widget.*
3. **Interactive controls are exempt from the click-to-comment handler.** The canonical
   contract hijacks clicks on any anchored element. On a page with accordions, tabs or
   real links that breaks the page in review mode — panels will not open and links will
   not follow. The handler now ignores clicks on `a[href], button, summary, [role="button"]`
   and leaves the **hover pill** as the comment affordance for those. Surfaced when the
   class accordion was added. *Candidate to harvest upstream: any consumer with an
   interactive surface hits this, and the workaround people reach for —
   `data-review-skip` on each control — silently makes those elements uncommentable.*

4. **MutationObserver guarded against its own output.** `paint()` writes `.rv-dots` into
   anchored elements, and the observer watches `childList` on the same subtree — so with
   one or more comments present it re-triggered itself indefinitely. The observer now
   disconnects around `anchorAll()` + `paint()` and calls `takeRecords()` before
   reconnecting. This is latent in any composition that pairs the anchor-extensibility
   observer with the status-indicator atomic, and it is invisible until the first comment
   exists. *Candidate to harvest upstream — likely the highest-severity of the four.*

5. **Breakpoint bound to `matchMedia`, not a one-shot `innerWidth` read.** A one-shot read taken while the viewport reports `0` (hidden pane, background tab) hides the sidebar, and the CSS hides the toggle at ≥1280px — leaving no way to reopen it. Binding both to the same media query, with a `change` listener, makes the states self-correct. Surfaced during verification. *Candidate to harvest upstream.*
